Ranking metric (design §7.67, since 2026-10-03): point-level F1 -- did the method find the experimental points (marker positions, which is what a human digitizer records)? Both sides are normalized by the axis range (log axes in log10), points are matched one to one within τ = 0.02 of the axis range, and the value shown is the mean over figures (macro); recall, precision and the mean distance of matched points (normalized units) are shown alongside. summary_score is the earlier curve-distance score, kept as a reference column so every earlier row stays comparable. τ = 0.01 / 0.05 and micro (pooled) values are in each results file's point_metrics.

Dense-marker figures (design §7.72, since 2026-10-04): a figure whose ground-truth markers sit closer together than 2τ (median within-series nearest-neighbour spacing in the axis-normalized space < 0.04) cannot be matched point by point. Those figures leave the point columns above (#figures shows point-scored / all) and are ranked separately by curve distance (summary_score) in the dense-marker tables below. summary_score (ref.) in the main table still covers every figure.

Runs (design §7.69, since 2026-10-04): where an LLM / VLM row ran. Cloud = a hosted model (Claude, run as a Claude Code subagent with tools); Local = an open-weight model on a laptop (Apple M3 Max 128GB, mlx-vlm, 8bit, one inference per figure, no network: HF_HUB_OFFLINE=1) -- nothing leaves the machine. Settings and parse-failure counts are in each local result's local_run; raw outputs in data/local_vlm_run_v3/ (v2 run: data/local_vlm_run_v2/). The v3 local run had the machine to itself, one model at a time, so its local_run.seconds_per_figure is comparable between models. A dash = not an LLM row (LineFormer, chart-to-table models).

Prompts (design §7.73 (2), since 2026-10-04): Claude rows marked v3 プロンプト (2026-10-04) are the current Claude rows: markers only, no fit / trend / guide / theory lines (scripts/eval/llm_run_v3_prompt.md).
