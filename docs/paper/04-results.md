## 4.3 順位として報告しない

本論文が主張するのは順位ではない。主表から読めるのは、桁の違う3つの層である。

- **クラウドの言語モデル(2026-10 の上位3モデル)**: 点 F1 0.92〜0.95(軸あり)
- **ローカル VLM**: 0.45〜0.73
- **専用モデル LineFormer と CV**: 0.02 以下

上位3モデル同士の差は、読み取りの精度ではなく、どの線を拾うかで決まっている(4.5)。

LineFormer と CV の点 F1 がほぼ0なのは、線を画素の列として密に出し、マーカーを1点として特定しないためである。再現率は 0.17〜0.26 あるが、適合率は 0.01 以下になる。これは「実験点を特定していない」ことの正しい反映である(3.2)。

**summary_score は差を隠す.** LineFormer は summary_score 0.7462 で点 F1 0.006、Qwen3.8-27B は 0.9243 で 0.631、2026-09 の Sonnet 5 は 0.9638 で 0.672 である。曲線距離では、線が正解点の近くを通り、系列の本数が合っていれば高い値が出る。Sonnet 5 は τ = 0.05 では 0.806 まで上がり、位置誤差も 0.0076 と上位より大きい。点の位置が 2% の内側に入っていない。

**位置誤差.** クラウドの上位3モデル(2026-10)の一致点の平均距離は軸レンジの 0.34〜0.46%(軸あり)で、注意深い人のクリック誤差として報告されている 0.1〜0.4%(3.3)と同じ程度である。ただし一致した点だけの平均であり、比べている相手も人のデジタイズそのものなので、モデルが人と同等の精度だという主張にはしない。

## 4.4 軸校正を外すとどうなるか

2026-10 の Claude 4モデルとローカル VLM 3モデルを、全97図で軸範囲を与えない条件でも測った(3.1: 範囲もスケールも渡さず、軸ごとの報告規則だけを渡す)。

| モデル | 実行 | 点 F1 軸あり | 点 F1 軸なし | 差 |
|---|---|---|---|---|
| Claude Opus 5.5 | クラウド | 0.951 | **0.986** | +0.035 |
| Claude Sonnet 5.5 | クラウド | 0.953 | 0.973 | +0.020 |
| Claude Fable 5.1 | クラウド | 0.917 | 0.934 | +0.017 |
| Gemma 4 31B | ローカル | 0.733 | 0.745 | +0.012 |
| Qwen3.8-27B | ローカル | 0.631 | 0.658 | +0.027 |
| Qwen3.5-9B | ローカル | 0.446 | 0.470 | +0.024 |
| Claude Haiku 4.5 | クラウド | 0.030 | 0.031 | +0.001 |

(密でない80図、τ = 0.02。)

密な17図の summary_score では、Claude 上位3モデルが 0.942〜0.965 → 0.943〜0.944 とほぼ変わらず、ローカル VLM では Gemma 4 31B が 0.810 → 0.855 と上がり、Qwen3.8-27B が 0.926 → 0.827 と下がった。Haiku 4.5 は 0.618 → 0.273 である。

**密でない80図では、軸の範囲を与えなくてもどのモデルも落ちない。** むしろわずかに上がる。Opus 5.5 の +0.035 の大半は適合率(0.932 → 0.985)で、軸なし条件では近似線を出さなかったためである(4.5)。それ以外のモデルについて、軸を与えたほうが低くなる理由はこの測定からは分からない。

2026-09 に Claude 5 系で同じ比較を10図(現在の採点対象では8図)で行ったときは、summary_score が一様に 0.08〜0.13 下がった(例: Opus 5 0.9900 → 0.9133)。その低下は**軸表記に罠のある図に集中していた** — 軸タイトルに置かれた ×10ⁿ、1000/T のような逆数軸、log10 値で印字された対数軸。今回はその慣習を報告規則として渡しているので、残るのは目盛の幾何的な読み取りで、そこはボトルネックではないことが97図で確認できた。

したがって正確な主張は次のとおりである。**目盛の位置と値を読むことは解けている。軸表記の慣習を解釈することは、この測定では測っていない**(規則として与えた)。完全なエンドツーエンドの軸読み取りではない。

軸なし条件で例外的に大きく落ちる図は、クロップの際に目盛ラベルが切れて写っていない図である(44283-39575 など)。モデルは同じ論文の別の図から軸を推測していた。この条件では原理的に解けない(7.7)。

## 4.5 上位モデルを分けているのは「どの線を拾うか」

Opus 5.5 は軸あり条件で、13図で**図中の近似線(fit)も系列として出力した**(100図時点の集計、design §7.66)。正解データ(Starrydata)はマーカーの点だけを持つので、近似線は余計な点として適合率を下げる。主表で Opus 5.5 の再現率は 0.989 と最も高いが、適合率は 0.932 にとどまる。同じ Opus 5.5 が軸なし条件では近似線を出しておらず、適合率 0.985、点 F1 0.986 で首位になった。

これはプロンプトの不備である。v2 プロンプトは「参照・比較曲線は含める」と書いたが、近似線の扱いを指定しなかった。モデルの能力差として読んではいけない。近似線・ガイド線・理論曲線を出さないよう明記した v3 プロンプトでの再実行を進めている(7.5)。本章の Claude の数値はすべて v2 以前のプロンプトによる。

9月の実行でも同じ構造が見えていた。

| モデル(2026-09) | 予測系列数 / 実際(実行時の記録) | 点 F1(80図) |
|---|---|---|
| Opus 5 | 中央値 1.00 / 平均 0.99 | 0.918 |
| Sonnet 5 | 中央値 1.00 / 平均 1.00 | 0.672 |
| Fable 5 | 中央値 1.00 / 平均 1.00 | 0.941 |
| **Haiku 4.5** | 中央値 2.50 / **平均 3.10** | **0.039** |

Haiku 4.5 は2回とも、非白ピクセルの連結成分を色でまとめる画像処理を自分で書き、1本の線を複数の系列に断片化した。2026-10 の軸なし条件では1図あたり平均約7系列(正解は約4)を出し、カバレッジは 0.21 だった。9月の10図サブセットで画像を直接読んだときの Haiku は summary_score 0.8788 を出している。**低いスコアは読み取りの失敗ではなく手法の選択である。**

ここから導かれる注意がある。**これはモデルの測定ではなく、ツールを自由に使えるエージェントの測定である。** 同じモデルでも、実行ごとに選ぶ手法と拾う線が変わる。ローカル VLM はツールを使わない1回の推論なので、この点で条件が違う(3.8)。

## 4.6 再現性について

Haiku 4.5 の 2026-09 の実行は、出力ファイルが途中で3回変化し、完了報告がファイルの中身と一致しなかった(`data/llm_subset_rest/RUN_NOTES.md`)。2026-10 の実行でも、軸ありの後半バッチは一度ピクセル単位の430万点を書いた後、自分で書き直して2万点の版に置き換えた。

この経験から、2026-10 の実行では次の手順を取った。

- 回答は終わったバッチから即座にリポジトリへ保存し、短いファイルで上書きしない
- 件数はエージェントの自己申告ではなく、ファイルの中身で確認する(全16バッチで一致した)
- プロンプトをリポジトリに保存する(`scripts/eval/llm_run_v2_prompt.md`)

ローカル VLM の生の応答は `data/local_vlm_run_v2/` に保存した。応答が解析できなかった図(大半は 8192 トークンの上限で切れたもの)は全点見逃しとして採点しており、その数は結果ファイルの `local_run` に記録している(6.3)。

公表値はすべて、保存したファイルから再計算できる。
