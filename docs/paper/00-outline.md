# real-chart-bench 論文 — 構成(2026-09-30 改訂)

## 改訂の理由

初稿はデータセットの素性と正解データの品質から入り、その中に「2.75px の系統誤差」の節と図を2枚置いていた。オーナー指摘により2点を変える。

1. **2.75px の節と図2・図4を削除。** あれは我々の注釈パイプラインのバグ(視覚モデル2つが目盛ではなくラベル文字の上端を測っていた)を我々が直した話で、データの性質でもタスクの難しさでもない。論文に載せる価値がない。
2. **手法を先に置く。** ベンチマーク論文は「どう作ったか」が主張の中心。正解データの品質は手法の一部として扱う。

さらに、測定が出揃ったことで主題が変わった。**言語モデルがこのタスクでどこまで到達するかが最も情報量のある結果**であり、そこを軸に据える。

## 主張の骨格

1. 実論文の図でベンチマークを作ると、合成図では現れない障害が支配的になる — ペアリング、単位空間、パネル分割、クロップ
2. その条件下で、フロンティア言語モデルは軸校正を与えられれば **0.96〜0.98** に達し、素朴なCVベースライン(0.7390)を大きく上回る
3. ただし**上位3モデルは分離できていない**(0.0166差)。順位ではなく「到達した」ことが結果
4. 軸校正を外すと **約0.11〜0.13 下がる**。低下は軸表記に罠のある図に集中する
5. スコア差の最大要因はモデルの読み取り精度ではなく**エージェントが選んだ手法**だった(Haikuの例)
6. 出力は人手で後編集できるので、完全自動の精度だけが指標ではない
7. クラウドに出せないデータには専用ローカルモデルの席がある — ただしその論拠には LineFormer の現行データでの再測定が要る(未了)
