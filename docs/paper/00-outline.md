# real-chart-bench 論文 — 構成(2026-10-06 改訂)

## 改訂の理由

2026-10-04 版からの変更点:

1. **データセットが 97 → 94図。** x 軸の目盛の数字が切り抜きで写っていない3図(44283 の 38971 / 39575 / 39636)を
   `axis_unreadable` で除外した(オーナー判断「A」、design §7.77)。密でない図は80図のまま、密な図は17 → 14図。
2. **Claude とローカル VLM の数値を v3 プロンプトの結果に差し替えた**(近似線・ガイド線・理論曲線を出さない、design §7.73 (2)、§7.74)。
   v2 の数値は履歴として残す。Opus 5.5 の適合率を下げていた近似線の問題は v3 で消えた(4.5)。
3. **合成図で学習したチャート専用モデルを評価対象に戻した**(オーナーが方針を改めた。旧 7 項「評価しない」は撤回、design §7.75)。
   DePlot / TinyChart / UniChart / Granite Vision / ChartGemma を、(a) 著者のテストデータと採点コードで論文値を再現し、
   (b) マーカー形式の既存の合成図(PlotQA dot_line 100図)で測り、(c) 実論文の図で測った。
4. **Claude も同じ合成図で測った**(design §7.80)。合成図では Claude とチャート専用モデルの差は小さく、実論文の図で大きく開く。
5. **量子化の影響を RTX 4090 で測った**(Qwen3.5-9B、bf16 / FP8 / 8bit / 4bit、design §7.75 (2))。
6. **「人が軸を校正し、AI が点を取る」条件(pixcal)を追加した**(design §7.76〜§7.78)。各図に目盛2本ずつのピクセル位置と値を渡す。
   単発の VLM 向けの2段階版(design §7.79)は 0.02〜0.03 で、分担が効くのはエージェントだけだった。
7. **除外した図の種類が実際の材料科学の論文に多く現れることを限界に明記した**(7.11、オーナー指摘)。
8. **新規性の書き方(1.2、design §7.70)はオーナー確認済み**(2026-10-06)。
9. **主条件を2つに絞った**(design §7.82、オーナー判断 2026-10-06)。主条件1「完全自動」(軸の情報なし)と主条件2「人が軸を校正」
   (目盛2本ずつのピクセル位置と値)。軸の値の範囲を渡す旧主条件は表から外し、「範囲を渡しても上位は変わらなかった」を数字つきで
   1文書くだけにした(4章冒頭、3.1)。
10. **学習を使わない CV ベースライン2種を外した**(design §7.82 追記)。既存の学習済みモデル(LineFormer、チャート専用モデル)が
    下限を示しているため。
11. **正解データを図の印字どおりにした**(design §7.82 (2))。log10 で印字された y 軸13本は log10 値、°C で印字された x 軸1本は °C。
    報告規則は全軸共通の「印字どおり」1文になった。点 F1 は全行で変わらない(2.6)。
12. **GPT を加えた**(design §7.81)。GPT-6.1-Sol を Codex CLI(ChatGPT Plus でログイン、API キーなし)で、Claude と同じ封印ディレクトリ・
    同じ指示文で測った。完全自動 0.978、人が軸を校正 0.861(手法の選択による低下、4.2)。GPT-5.5 は 0.451 / 0.279(目測で回答)。
13. **実行時間とトークン量を載せた**(design §7.82 (3))。「この実行のときはこうだった」という記録で、トークンは提供元をまたいで比べない。

## 主張の骨格

1. **この実験環境は機能している。** 合成図で学習したチャート専用モデルは、著者のテストデータと採点コードで論文の値を再現した
   (TinyChart RMS-F1 93.20、論文 93.78。DePlot PlotQA RNSS 97.27 / RMS-F1 94.52、論文 97.1 / 94.2)
2. **それらのモデルは、マーカー形式の合成図なら読める。** PlotQA dot_line 100図で点 F1 0.88〜0.96(ChartGemma のみ 0.50)
3. **実論文の実験グラフでは読めない。** 同じ指標で 0.04〜0.29。合成図の 5〜30% まで落ちる
4. **Claude エージェントは、合成図ではチャート専用モデルと同程度だが、実論文の図では桁が違う。**
   合成図で Opus 5.5 0.975 / Sonnet 5.5 0.966 / Fable 5.1 0.944(DePlot 0.959)、実論文の図(完全自動)で 0.95〜0.99。
   合成図の成績は、実論文の図での成績を予測しない
5. 評価は「実験点(マーカー)を見つけたか」を点単位で測る。曲線距離は差を隠す(LineFormer + 目盛校正: summary_score 0.890 に対し点 F1 0.033)
6. 条件は2つ。**完全自動**で、Claude の上位3モデルと GPT-6.1-Sol は点 F1 0.95〜0.99。**人が軸を校正**すると Claude の上位3モデルは
   0.97〜0.99 にそろい、人は軸の校正だけを行い点の抽出は AI に任せる分担が成り立つ。ただし分担が効くのは画像処理で位置を測る
   エージェントだけで、単発の VLM は下がり、GPT-6.1-Sol もその実行で選んだ手法のせいで 0.861 に下がった
7. データを外に出せない場面では、ローカルの汎用 VLM(最良は Gemma 4 31B で 0.73、1図平均 112秒)が、LineFormer やチャート専用モデルより
   桁違いに良い。8bit 量子化はほぼ無損失、4bit(RTN)は約 0.10 落ちる
8. 上位モデルの差は読み取り精度より「どの手法・どの線を選ぶか」で決まる(v2 の Opus 5.5 の近似線、Haiku 4.5 の断片化、
   GPT-6.1-Sol の手打ちの座標)。順位は報告しない
9. 出力は人手で後編集できるので、完全自動の精度だけが指標ではない
