## 改訂の理由

2026-09-30 版からの変更点:

1. **データセットが 106 → 100図。** 他論文の参照線・比較系列が描かれているのに正解データにない図を
   `gt_incomplete` として除外した(オーナー判断 2026-10-01、design §7.65)。28331-28500 は印字単位へ移した。
2. **メトリクスに正規化幅の下限**(線形 y 軸レンジの5%、design §7.66)。
3. **LLM を全図・2条件で再実行**(Opus 5.5 / Sonnet 5.5 / Fable 5.1 / Haiku 4.5、軸あり/軸なし)。
   軸なし条件が n=10 から n=100 になり、4章の結論が変わった。
4. **LineFormer を n=100 でローカル再測定**(RTX 4090)。6章の空白が埋まり、論旨を組み直した。

## 主張の骨格

1. 実論文の図でベンチマークを作ると、合成図では現れない障害が支配的になる — ペアリング、単位空間、
   パネル分割、クロップ、そして**正解データが図の全系列を持たないこと**
2. フロンティア言語モデルは軸校正を与えられれば **0.97〜0.98** に達し、素朴なCV(0.7366)と
   専用モデル LineFormer(0.7462)を大きく上回る
3. **軸の表記規則(印字どおり / log10 目盛は 10^値 / °C は K)を渡せば、目盛を自分で読ませても上位3モデルは
   落ちない**(軸なし 0.982〜0.985)。9月の10図で見えた −0.11〜−0.13 は表記の罠だった。完全な
   エンドツーエンドではない点は明記する
4. 上位モデルの差を決めているのは読み取り精度ではなく**エージェントがどの線を拾うか**(Opus 5.5 の近似線、
   −0.0215)。これはプロンプトの不備であり、順位は報告しない
5. 出力は人手で後編集できるので、完全自動の精度だけが指標ではない
6. LineFormer の失点の大半は**軸の置き方**(画像全体をプロット領域とみなす変換)で、目盛位置を与えれば
   0.73 → 0.87。ただし点だけの散布図では何も返さない。97%がマーカー図の本データセットでは、
   ローカル専用モデルの席は「軸検出を足し、マーカー図で再学習すれば」という条件付きの主張にとどまる
