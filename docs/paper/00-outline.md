# real-chart-bench 論文 — 構成(2026-10-04 改訂)

## 改訂の理由

2026-10-02 版からの変更点:

1. **主指標を点単位の F1 に変更**(τ = 軸レンジの2%、design §7.67、§7.71、§7.73)。系列は `1 − F1` で
   ハンガリアン法の1対1対応、点の一致は対応した系列の組の中だけで数える。曲線距離の `summary_score` は
   参考指標として残す。
2. **データセットが 100 → 97図。** 線だけの図3枚を `no_markers` で除外した(マーカーだけの図にする、
   design §7.71)。そのうち 4965-13164 は、元論文(PLOS ONE)の本文から、測定点ではなく計算値を滑らかに描いた線と判断した。
3. **マーカーが密な図17枚を副表に分けた**(design §7.72)。点単位の主表は80図、密な17図は曲線距離で別に集計する。
4. **ローカル VLM 3種を測定**(Gemma 4 31B / Qwen3.8-27B / Qwen3.5-9B、8bit、M3 Max のノート PC、design §7.69、§7.73 (3))。
   6章の「データを外に出せないときに何が使えるか」に数値が入った。
5. **人の精度上限**は、Starrydata の人手デジタイズを上限とみなし、デジタイザの精度に関する既存研究を引用する
   (オーナー見解、design §7.73 (4))。独自の再デジタイズは行わない。
6. **新規性の書き方を修正。** CHART-Infographics(ICPR 2020 以降)と PlotExtract(2025)が既に実図で評価している
   (design §7.70)。「実図で評価する初のベンチマーク」とは書かない。**オーナー・司令塔の確認待ち。**
7. 合成図で学習したチャート専用モデル(DePlot ほか)は6図で試したが、評価対象にしない(オーナー判断、design §7.73 (5))。
8. 近似線を出さないよう指示した v3 プロンプトでの再実行が進行中(design §7.73 (2))。本稿の Claude の数値は v2 プロンプトによる。

## 主張の骨格

1. 実論文の図でベンチマークを作ると、合成図では現れない障害が支配的になる — ペアリング、単位空間、
   パネル分割、クロップ、**正解データが図の全系列を持たないこと**、そして**マーカーが密な図では人の正解も
   全マーカーを取っていないこと**
2. 評価は「実験点(マーカー)を見つけたか」を点単位で測る。曲線距離は、近似線をなぞった予測や系列の本数が
   合うだけの予測にも点を与え、差を隠す(LineFormer: summary_score 0.746 に対し点 F1 0.006)
3. τ = 2% は注意深い人のクリック誤差(軸レンジの 0.1〜0.4%)より 5〜20 倍緩い。測っているのはクリックの
   精度ではなく、**正しい系列の正しい点を、正しい軸校正で取れるか**である
4. クラウドの言語モデル(エージェント。2026-10 の Opus 5.5 / Sonnet 5.5 / Fable 5.1)は点 F1 で **0.92〜0.99**、ローカル VLM の最良(Gemma 4 31B)は
   **0.73〜0.75**、LineFormer と CV は **0.02 以下**。軸の範囲を与えなくても上位は落ちない
   (軸の表記規則は渡している)
5. 上位モデルの差は読み取り精度より**どの線を拾うか**(Opus 5.5 の近似線)で決まる。順位は報告しない
6. 出力は人手で後編集できるので、完全自動の精度だけが指標ではない
7. データを外に出せない場面では、ノート PC で動く汎用 VLM が専用モデル・CV より桁違いに良いが、
   クラウドとはまだ 0.2 以上の差がある
