## 主張の骨格

1. **この実験環境は機能している。** 合成図で学習したチャート専用モデルは、著者のテストデータと採点コードで論文の値を再現した
   (TinyChart RMS-F1 93.20、論文 93.78。DePlot PlotQA RNSS 97.27 / RMS-F1 94.52、論文 97.1 / 94.2)
2. **それらのモデルは、マーカー形式の合成図なら読める。** PlotQA dot_line 100図で点 F1 0.88〜0.96(ChartGemma のみ 0.50)
3. **実論文の実験グラフでは読めない。** 同じ指標で 0.05〜0.28。合成図の 5〜30% まで落ちる
4. **Claude エージェントは、合成図ではチャート専用モデルと同程度だが、実論文の図では桁が違う。**
   合成図で Opus 5.5 0.975 / Sonnet 5.5 0.966 / Fable 5.1 0.944(DePlot 0.959)、実論文の図(完全自動)で 0.95〜0.99。
   合成図の成績は、実論文の図での成績を予測しない
5. 評価は「実験点(マーカー)を見つけたか」を点単位で測る。曲線距離は差を隠す(LineFormer + 目盛校正: summary_score 0.889 に対し点 F1 0.033)
6. 条件は2つ。**完全自動**で、Claude の上位3モデルと GPT-6.1-Sol は点 F1 0.95〜0.99。**人が軸を校正**すると Claude の上位3モデルは
   0.97〜0.99 にそろい、人は軸の校正だけを行い点の抽出は AI に任せる分担が成り立つ。ただし分担が効くのは画像処理で位置を測る
   エージェントだけで、単発の VLM は下がり、GPT-6.1-Sol もその実行で選んだ手法のせいで 0.861 に下がった
7. データを外に出せない場面では、ローカルの汎用 VLM(最良は Gemma 4 31B で 0.73、1図平均 112秒)が、LineFormer やチャート専用モデルより
   桁違いに良い。8bit 量子化はほぼ無損失、4bit(RTN)は約 0.10 落ちる
8. 上位モデルの差は読み取り精度より「どの手法・どの線を選ぶか」で決まる(v2 の Opus 5.5 の近似線、Haiku 4.5 の断片化、
   GPT-6.1-Sol の手打ちの座標)。順位は報告しない
9. 出力は人手で後編集できるので、完全自動の精度だけが指標ではない
10. **出所の違う正解データ(CHART-Infographics、582図)でも、上位のエージェントは高い水準を出す**が、本研究の77図より 0.1 低い。
    そのかなりの部分は正解データの書き方の規約と採点方式による。規約にプロンプトを合わせれば数字は上がるが、それはしない(4.8、7.5)
11. **データを外に出せない場面でも、ローカルのモデルをエージェントとして動かせばクラウドに近づく**(Qwen3.8-27B、人が軸を校正して 0.913)。代償は1図十数分の時間(6.3)
