## 8.2 優先順位

**1. v3 プロンプトの結果で数値を差し替える。**
7.5 のとおり、Opus 5.5 の適合率は近似線を拾うかどうかで決まっていた。v3 で近似線の影響を除き、上位モデルの差が読み取り精度の差として残るかを確かめる。本稿の4章・6章の Claude とローカル VLM の数値は v3 の結果で置き換える。

**2. 新規性の書き方を確定する。**
1.2 の差分の書き方(design §7.70)は、オーナー・司令塔の確認待ちである。

**3. データセットを拡大する。**
7.1 のとおり、上位モデルの分離には規模が足りない。分野の偏り(熱電材料、温度依存性のプロット)も解消したい。学習データの汚染(7.10)を避けるため、モデルの学習データの締切日以降に出版された論文の図を別セットとして持つことも検討する。

**4. 未決の判断。**
- `gt_incomplete` の図を補足デジタイズで採点に戻すか(7.6)
- 密な図で、人が取っていないマーカーをどう扱うか(7.4)
- 目盛校正版 LineFormer を参考行として表に残すか(6.3)
- 軸表記の解釈そのものを測る条件(報告規則を渡さない)を設けるか(7.7)
- 人と同等のクリック精度を区別する副指標(τ = 0.5% 程度)を併記するか(3.3)

## 8.4 再現性

- リポジトリ: 全スクリプト、レジストリ、正解データ、生のモデル出力を含む
- 言語モデルの生回答は `data/llm_subset_*/predictions/`(2026-09)と `data/llm_run_v2/`(2026-10)に保存されており、メトリクスを変更して再採点できる。2026-10 の実行はプロンプトも保存している(`scripts/eval/llm_run_v2_prompt.md`、v3 は `scripts/eval/llm_run_v3_prompt.md`)
- ローカル VLM の生の応答は `data/local_vlm_run_v2/` にあり、実行環境(モデルのリビジョン、mlx-vlm の版、生成設定)は各結果ファイルの `local_run` と `scripts/eval/local_vlm/README.md` に記録している
- LineFormer の生のピクセル出力は `data/lineformer_predictions/` にあり、ピクセル→数値の変換を変えても GPU なしで再採点できる
- 単位移行後も旧空間の回答を採点できるよう、変換テーブルを採点時に適用する(生ファイルは未改変)
- 主指標の変更(曲線距離 → 点単位)も、モデルを再実行せず保存済みの回答の再採点だけで行った
- `dataset_version` は件数から導出され、異なる母集団の混同を防ぐ
