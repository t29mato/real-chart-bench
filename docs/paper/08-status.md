## 8.2 優先順位

**1. データセットを拡大する。**
7.1 のとおり、上位モデルの分離には規模が足りない。分野の偏り(熱電材料、温度依存性のプロット)も解消したい。学習データの汚染(7.10)を避けるため、モデルの学習データの締切日以降に出版された論文の図を別セットとして持つことも検討する。

**2. 除外した図を評価に戻す。**
7.11 のとおり、除外した図の種類(参照線を含む図、複数パネル、線だけの図)は実際の論文に多い。補足デジタイズで `gt_incomplete` の図を採点に戻すところから始める。

**3. 合成図の比較を広げる。**
PlotQA dot_line は x が離散(年)で対数軸がない。数値の x を持つ散布図(ChartNet など)での比較は未試行である。

**4. CHART-Infographics の実図で、同じモデルを測る。**
CHART-Infographics(UB-PMC)は、本研究と同じ「実図・CC BY / CC-0・人手注釈」のデータセットでありながら、収録元が生物医学(PubMed Central)で、公開された先行手法のスコアがある(1.2)。同じ Claude / GPT / ローカル VLM をそこで測れば、次の2つが分かる。

- **2020年の畳み込みモデルから現在の言語モデルまでの改善幅**が、同一データ・同一指標で言える(ICPR 2020 Task 6b の実図 data-score 0.552〜0.765 が出発点)
- **本研究の結果が材料科学に固有でないこと**の確認、あるいは固有であることの発見

使えるのは注釈にデータ値が入っている図に限られる。ICPR 2022 と 2024 の訓練セットを実測した(`docs/experiments/2026-10-06-chartinfo-dataset-audit.md`)。

| | ICPR 2022 | ICPR 2024 |
|---|---|---|
| 図数 | 22,923 | 36,182 |
| データ値あり | 4,293(18.7%) | 5,427(15.0%) |
| **x が数値 — 本研究の指標で使える** | **1,748** | **2,214** |
| 内訳 | line 1,256 / scatter 492 | line 1,622 / scatter 592 |
| **scatter-line** | **1,818図すべて注釈なし** | **3,446図すべて注釈なし** |

データセットが注釈より速く拡大しているため、割合は下がり絶対数は増えている。**scatter-line は2年で 1,818 → 3,446図に倍増したが、データ段階に到達した図は両版とも7図のまま**で、実図の scatter-line としては世界最大の収集でありながらデータ抽出には使えない。棒・箱は x がカテゴリ軸なので本研究の指標の対象外である。

注意として、**この比較は先行研究チーム自身が実施する可能性が高い**(8.5)。優先順位はその前提で決める。

**5. 未決の判断。**

- 軸表記の慣習(軸タイトルの倍率)の解釈そのものを測る条件を設けるか(7.7)

## 8.4 再現性

- リポジトリ: 全スクリプト、レジストリ、正解データ、生のモデル出力を含む
- 言語モデルの生回答は `data/llm_subset_*/predictions/`(2026-09)、`data/llm_run_v2/`、`data/llm_run_v3/`、`data/llm_run_pixcal/`、`data/llm_run_codex/`(GPT、イベントログつき、実論文の図)、`data/synthetic/plotqa_dot_line/llm_run/`(合成図)に保存されており、メトリクスを変更して再採点できる。プロンプトも保存している(`scripts/eval/llm_run_*_prompt.md`)
- ローカル VLM の生の応答は `data/local_vlm_run_v2/`、`data/local_vlm_run_v3/`(Mac)、`data/local_vlm_run_cuda/`、`data/local_vlm_run_cuda_pixcal/`(RTX 4090)にあり、実行環境(モデルのリビジョン、エンジンの版、生成設定)は各結果ファイルの `local_run` と `scripts/eval/local_vlm/README.md` に記録している
- チャート専用モデルの生出力は `data/chart2table_predictions/`、論文値の再現の出力は `data/repro_predictions/` にあり、著者の採点コードを `scripts/eval/repro/third_party/` に無改変で置いている
- LineFormer の生のピクセル出力は `data/lineformer_predictions/` にあり、ピクセル→数値の変換を変えても GPU なしで再採点できる
- 単位移行後も旧空間の回答を採点できるよう、変換テーブルを採点時に適用する(生ファイルは未改変)。印字どおりの表記への移行(log10、°C)も同じく採点時の逆変換で扱う(`adapter/printed_space.py`)
- 実行時間とトークン量の元データは `data/run_costs/` に保存している
- 主指標の変更(曲線距離 → 点単位)も、図の除外も、モデルを再実行せず保存済みの回答の再採点だけで行った(`scripts/eval/rescore_all.py`)
- `dataset_version` は件数から導出され、異なる母集団の混同を防ぐ

## 8.5 先行研究チームの動向

CHART-Infographics を運営しているのは **University at Buffalo(CSE)の Srirangaraj Setlur / Venu Govindaraju** のグループと、**Kenny Davila**(初期は UB、現在は DePaul University)である。ICDAR 2019 / ICPR 2020 / ICPR 2022 の3回はここに Adobe Research(Chris Tensmeyer ら)が合成データで加わっていた。

直近の **CHART-Info 2024**(ICPR 2024)では体制が変わっている。Davila(DePaul)、UB(Fei Xu、Setlur、Govindaraju)に加え、**IIIT Hyderabad(Rupak Lazarus、Ajoy Mondal、C. V. Jawahar)** と Universidad Tecnológica Centroamericana(ホンジュラス)が参加した。データセットは20種・12万枚規模に拡大し、競技会形式からオフラインのベンチマークへ移行している。

**本研究にとって重要な観測が2つある。**

1. **CHART-Info 2024 は、7タスクのうち最初の5タスクにしかベースラインを与えていない。** データ抽出(Task 6)とエンドツーエンド(Task 7)のベースラインは論文にない。注釈は 5,427図(訓練)/ 2,676図(評価)で用意されているので、**データが揃っているのに測られていない状態**である。
2. **論文本文に LLM / VLM への言及がない。** 畳み込みモデルと Transformer 系の認識器が対象で、2024年時点の大規模言語モデルは評価対象に入っていない。

この2点は、「同じモデルを CHART-Infographics で測る」(8.2 の4)が**まだ誰もやっていない空白**であることを示す。一方で、データも注釈も採点コードも彼らの手元にあるので、**実施する能力は完全にある**。彼らが次版でこれを埋めるのは自然な流れであり、本研究が同じことをする場合、優位性は速度にしかない。

本研究の立ち位置は、むしろ重ならない側にある。ただし**分野の違いを差分として主張することはできない**。CHART-Info 2024 の訓練セット 36,182図の内訳は、XY プロット系(line + scatter + scatter-line)が 55.3%、棒グラフが 29.4%、円グラフが 1.2% である。生物医学でも XY プロットが過半数を占め、円グラフはほとんど現れない。材料科学の図の分布がこれと大きく違うという根拠は、本研究の側にはない — こちらのデータセットは XY プロットを選んで構築しているので、比較できる母集団を持っていないためである(オーナー指摘、2026-10-06)。

実際の差分は、分野ではなく次の3点にある。

1. **正解データの出所.** CHART-Infographics はベンチマークのために注釈者を雇って作る。本研究は Starrydata という独立した専門家のデジタイズ DB との照合で得る(2.2)
2. **系列の網羅.** 本研究は採点対象の全94図で全系列の点が揃っている。CHART-Infographics はデータ注釈まで到達した図が一部で、scatter-line は0図(上記)
3. **評価の粒度.** 本研究は点単位の F1(3.2)、CHART-Infographics はしきい値なしの割り当てコスト(3.5)

同じ土俵で competitor になるより、互いの欠けを補う関係として扱うほうが正確である。
