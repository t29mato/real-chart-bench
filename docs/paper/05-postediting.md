# 5. 人手による後編集

## 5.1 完全自動の精度だけが指標ではない

本ベンチマークの評価系は、抽出結果を正解データと突き合わせて**完全自動での正確さ**を測る。しかし実際のデジタイズ作業では、抽出結果は出発点であって終点ではない。

Starrydata Digitizer は、論文の図から XY データを起こすための Web ツールであり、**抽出結果を読み込んでその上で人手編集できる**。点を動かす、系列を分割・統合する、誤検出を削る、取りこぼしを足す。本ベンチマークで測っている出力は、そのまま編集の初期値になる。

これが意味するのは、**実運用で効くのは平均誤差ではなく修正コスト**だということである。

## 5.2 平均誤差と修正コストは別の量である

4.5 の Haiku の例が分かりやすい。点 F1 0.039(2026-09 の実行)は低いが、実行の記録で目立つのは「点の位置が間違っている」ことではなく「1本の線を平均3本に切った」ことである(どちらがどれだけ点 F1 を下げたかは分解していない)。後編集の観点では、この2つの誤りのコストは全く違う。

- 系列を切りすぎている → 統合操作で直る。点の位置自体は使える
- 点の位置がずれている → 全点を測り直す必要がある
- 系列を取りこぼしている → その系列を一から起こす必要がある

現在のメトリクスはこれらを区別しない。点単位の再現率・適合率・位置誤差と、参考指標の `match_rate` を分けて報告しているので原理的には読み取れるが、**修正コストの指標としては設計していない**。系列を切りすぎた予測は、系列の1対1対応(3.2)で切れ端の大半が対応先を失い、点の位置が正しくても見逃しと余計な点として数えられる。

## 5.3 v2 で測るべきもの

本バージョンでは後編集の可能性を**運用上の事実として記述するにとどめ**、修正コストのメトリクスは導入しない。導入するなら以下を測ることになる。

- **使える出発点になっている図の割合** — 一から起こすより速いか
- **修正操作の回数** — 統合 / 分割 / 点移動 / 系列追加の別に
- **系列同定の正誤** — 点の精度とは独立に

この分離ができれば、「言語モデルは平均誤差では勝つが系列の取りこぼしがある」「専用モデルは平均誤差で劣るが構造が安定している」といった性質を分けて議論できる。4.5 の近似線の例(Opus 5.5)も同じで、後編集では余分な系列を1本消すだけの誤りが、現在のスコアでは適合率の低下(0.932、軸なし条件では 0.985)として現れる。現在のスコアはこれらを1つの数に潰している。

## 5.4 データセットとツールの関係

本ベンチマークの正解データは Starrydata Digitizer で作られたものである。つまり**ベンチマークの出力を同じツールに戻せる**。抽出手法の改善が、そのまま正解データの生産速度の改善につながる経路がある。

これは合成図ベンチマークにはない性質である。合成図で高得点を取る手法が実データの生産に寄与する保証はないが、ここでは測っている図がそのまま作業対象である。
