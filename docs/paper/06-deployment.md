# 6. 配備制約 — クラウドに出せないデータ

## 6.1 スコアが最も高い手法が、常に使える手法とは限らない

4章の結果は、フロンティア言語モデルがこのタスクで 0.96〜0.98 に達することを示した。しかしこれらはすべてクラウド API 経由のモデルである。

デジタイズの実運用では、クラウドに送れない図がある。

- **公開前の論文** — 査読中・エンバーゴ期間中の図
- **共同研究先から受領した未公表データ**
- **CC BY でない論文の図** — 本ベンチマークのデータセット自体は CC BY のみだが、実作業ではそうでない図も扱う

この制約は「AI を使うかどうか」ではなく「**データがどこへ出るか**」の問題である。完全にローカルで動くモデルは、プライバシー上は画像編集ソフトで PNG を開くのと変わらない。

## 6.2 「ローカル」の検証

実際に確認すべき点が3つある。

**1. 本当にローカルか。** テレメトリ、クラッシュレポート、実行時の重みダウンロード(HuggingFace hub への通信)、自動更新チェック。ネットワークを遮断して動作するかを確認するのが唯一の検証法である。

なお **Colab はローカルではない。** 本プロジェクトでも LineFormer をローカル環境でビルドできず Colab 経由に切り替えた経緯があるが、「クラウドに出せないデータ」を動機とする議論の証拠を Google のマシンで取れば主張が崩れる。この点は測定環境の選択に直接影響した(8章)。

**2. 重みのライセンス。** データが外に出なくても、non-commercial / research-only の重みは「再配布するデータベースを作る」という下流利用を禁じている場合がある。図のライセンスに対して行っているのと同じ規律で、**評価対象ツールごとにライセンス列を持つべき**である。

**3. データ側の義務。** NDA やエンバーゴが禁じているのは通常「第三者への開示」であって「手元でどのソフトを動かすか」ではない。ローカル処理は通常許容される。実際に効いてくるのは、元論文の公開前に派生 XY データを公表してしまうことであり、これは AI の問題ではなく公開タイミングの問題である。

## 6.3 この論拠は、まだ数字で裏付けられていない

本節の主張 —「フロンティア LLM が最強でも、実デジタイズ作業の相当部分では使えない。だから専用ローカルモデルには席がある」— は**動機としては述べられるが、証拠が揃っていない。**

LineFormer の測定は `v0-eval-pilot-n42` の古いデータセットでのものであり、現行の106図では未測定である(4.1で空欄にした理由)。LineEX も合成データ43万枚で学習されており、実図での汎化は未検証である。

したがって現時点で言えるのは以下までである。

- 配備制約は実在し、クラウド API を使えない場面がある
- その場面でローカルモデルが**十分な代替になるかは未検証**

この空白を埋めることが最優先の残作業である(8章)。
