# 6. 配備制約 — クラウドに出せないデータ

## 6.1 スコアが最も高い手法が、常に使える手法とは限らない

4章の結果は、フロンティア言語モデルがこのタスクで 0.97〜0.98 に達することを示した。しかしこれらはすべてクラウド API 経由のモデルである。

デジタイズの実運用では、クラウドに送れない図がある。

- **公開前の論文** — 査読中・エンバーゴ期間中の図
- **共同研究先から受領した未公表データ**
- **CC BY でない論文の図** — 本ベンチマークのデータセット自体は CC BY のみだが、実作業ではそうでない図も扱う

この制約は「AI を使うかどうか」ではなく「**データがどこへ出るか**」の問題である。完全にローカルで動くモデルは、プライバシー上は画像編集ソフトで PNG を開くのと変わらない。

## 6.2 「ローカル」の検証

実際に確認すべき点が3つある。

**1. 本当にローカルか。** テレメトリ、クラッシュレポート、実行時の重みダウンロード(HuggingFace hub への通信)、自動更新チェック。ネットワークを遮断して動作するかを確認するのが唯一の検証法である。

**Colab はローカルではない。** 「クラウドに出せないデータ」を動機とする議論の証拠を Google のマシンで取れば主張が崩れる。そこで LineFormer は、旧測定で使った Colab ではなく、ローカルの GeForce RTX 4090 で測り直した(6.3)。推論は100図で約8秒である。

**2. 重みのライセンス。** データが外に出なくても、non-commercial / research-only の重みは「再配布するデータベースを作る」という下流利用を禁じている場合がある。図のライセンスに対して行っているのと同じ規律で、**評価対象ツールごとにライセンス列を持つべき**である。

**3. データ側の義務。** NDA やエンバーゴが禁じているのは通常「第三者への開示」であって「手元でどのソフトを動かすか」ではない。ローカル処理は通常許容される。実際に効いてくるのは、元論文の公開前に派生 XY データを公表してしまうことであり、これは AI の問題ではなく公開タイミングの問題である。

## 6.3 ローカル専用モデルの実測 — LineFormer

LineFormer(ICDAR 2023、事前学習済み)を、他の全手法と同じ100図・同じ軸範囲で測った。

| 手法 | n | summary_score | match_rate | 曲線距離 | カバレッジ |
|---|---|---|---|---|---|
| LineFormer(事前学習、ローカル) | 100 | 0.7462 | 0.8220 | 0.2949 | 0.7116 |
| naive-cv(色相バケット) | 100 | 0.7366 | 0.7145 | 0.3771 | 0.8724 |

平均では naive-cv とほぼ同点である。図ごとには LineFormer の勝ち35・負け46・引き分け19(±0.02)。弱点は相補的で、LineFormer は系列をより多く見つけて形もより正しく追うが、線の端まで被覆しない。naive-cv が0点になる黒・灰色の線の7図では、LineFormer は 0.615 を取る。

ローカル環境での注意点が一つある。OpenMMLab の配布サーバ(`download.openmmlab.com`)が組織のプロキシ越しに届かず、旧測定と同じ版の mmcv-full を入手できなかった。mmcv-full 1.7.2 をソースからビルドし、torch は 2.1.2+cu121 とした。合成図3枚のスコアは旧測定と一致している(0.9166 対 0.917)。

### 失点の大半は軸の置き方

LineFormer は線を検出するが、軸は検出しない。採点では旧測定と同じく、検出したピクセル座標を「画像全体 = プロット領域」として数値に直している。論文の図には軸の外側に余白・目盛ラベル・軸タイトルがあるので、その分だけ値がずれる。

同じ検出結果を、人手レビュー済みの目盛ピクセル位置で数値に直した参考値を測った(目盛位置が現行の画像・軸範囲と一致する47図)。

| 同じ47図で | summary_score |
|---|---|
| LineFormer(画像全体で変換、公式の行) | 0.7302 |
| **LineFormer + 目盛位置(参考)** | **0.8739** |
| naive-cv | 0.7901 |
| Claude Fable 5.1 | 0.9851 |

軸の置き方だけで +0.14 である。この参考値は「軸情報を外部から与えた LineFormer」であって、そのまま使える手法ではない。リーダーボードでは別表の参考行として扱う。

### 点だけの散布図では何も返さない

LineFormer の0点は3図あり、いずれも点を結ぶ線のない散布図である。検出候補の信頼度は最高でも 0.000〜0.048 で、採用しきい値 0.3 を大きく下回る。線と点の両方が描かれた図では 0.93 程度の信頼度で正しく検出する。LineFormer は線のインスタンスを切り出すモデルであり、点の列は想定外の入力である。

本データセットは100図中97図がマーカー(散布点)を含む図である。目盛で校正してもなお残る 0.87 と 0.985 の差は、この不一致と整合する。

## 6.4 配備制約の論拠として言えること

測定が揃ったので、6.1 の主張を数字で書き直せる。

- 配備制約は実在し、クラウド API を使えない場面がある
- その場面で**現状の事前学習済み LineFormer をそのまま使うと、素朴なCVと同程度(0.75)**にとどまる。言語モデル(0.97〜0.98)の代替にはならない
- ただしその差の内訳は「読めない」ではない。**軸を見つけない**ことと、**点の列を線と認識しない**ことである。前者は軸検出を組み合わせれば埋まる部分があり(参考値で 0.87)、後者は学習データの問題である

したがって「ローカル専用モデルには席がある」は、**軸検出を加え、マーカー図を含むデータで学習し直せば**という条件付きの主張にとどまる。そのような改良を加えた手法の測定は、本ベンチマークで行える。
