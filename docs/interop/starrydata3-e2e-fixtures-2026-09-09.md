# real-chart-bench → Starrydata3 E2E フィクスチャ束(2026-09-09、**2026-09-11 改訂**)

Starrydata3 のデジタイズ画面 E2E 回帰テスト向けに、real-chart-bench から
**実論文の図 21 枚 + 軸校正(ピクセル位置つき) + 全プロット点(データ座標とピクセル座標の両方)**
を切り出したものです。「ここを校正して、ここを打つと、この数値になる」がそのまま書けます。

```
fixtures.json          全メタデータ・軸校正・点データ(約540KB)
images/                図の画像 21 枚(PNG/JPEG、計 2.6MB)
overlays/              検証用: 導出ピクセルを画像上に描いたもの。テスト入力ではない
```

## 2026-09-11 改訂の内容

**同じ論文の複数図が要る**というご要望に対応して 12 枚追加し、9 枚 → 21 枚になりました。
**5 本の論文が複数図を持ちます**(最大 5 枚)。既存 9 枚は差し替えていないので、
組んである E2E はそのまま動きます。

## 使い方

`fixtures.json` の `figures[]` が図 1 枚に対応します。

```jsonc
{
  "image": { "file": "images/27759_25217.jpg", "width_px": 1000, "height_px": 828, "sha256": "..." },
  "axis_calibration": {
    "x": { "scale": "linear",
           "p1": { "value": 400,  "px": 220.0 },     // 校正点1: 値と画像上のx座標
           "p2": { "value": 1000, "px": 962.25 },    // 校正点2
           "unit": "K", "axis_label_raw": "Temperature (K)" },
    "y": { "scale": "log",
           "p1": { "value": 0.1,    "px": 718.0 },   // y は px = 画像上のy座標(下向き正)
           "p2": { "value": 100000, "px": 20.25 },
           "unit": "S/m" },
    "resolution": { "x": { "units_per_px": 0.808353 }, "y": { "decades_per_px": 0.008599 } }
  },
  "series": [
    { "series_index": 0, "unit_x": "K", "unit_y": "S/m", "n_points": 7,
      "points": [ { "x": 373.3066, "y": 0.2351526, "px": 186.978, "py": 674.815 }, ... ] }
  ]
}
```

- 軸は **2 点校正**そのものです。`p1`/`p2` の `px` に校正点を置き、`value` を入力する
- `scale` は `"linear"` か `"log"`。log 軸は log10 で内挿します
- 各点の `px`/`py` が画像上の位置、`x`/`y` が期待される数値
- `resolution` は 1px あたりの値の変化量です。**アサーションの許容誤差はここから決めてください**
  (例: `units_per_px: 0.808` の軸で ±2px を許すなら許容誤差 ±1.6)

`py` は画像座標なので下向きが正、`p1`(小さい値)の `px` が `p2` より大きくなります。

## ピクセル座標の素性(重要)

- **軸のピクセル位置は実測値**です。印字された目盛ラベルとその位置を 2 つの vision モデルに
  独立に読ませて突き合わせ、さらにオーナーが画像と照合済みのものだけを使っています
  (`axis_calibration.provenance` に図ごとのモデル間不一致 px が入っています)
- **点のピクセル位置は導出値**です。当リポジトリの正解データはデータ座標しか持たないため、
  上の軸校正を通して逆写像しています。したがって **pixel → value の往復は定義上厳密**
  (今回の束で相対誤差 最大 4.9e-4、これは px を小数3桁に丸めた分)。
  E2E のオラクルとしてはこれで十分なはずです
- 導出ピクセルが**実際に描かれているマーカーの上に乗るか**は数式では保証されないので、
  21 枚すべて `overlays/` を目視確認済みです。加えて機械的にも、導出点から最も近いインクまでの
  距離の中央値が 0〜1.4px(塗りマーカーの図)、中空マーカーの図はマーカー半径分だけ離れる、
  という想定どおりの数字になっています

### 図ごとの注意点

- **27759/16(a) は凡例が 5 系列、GT は 4 系列**です。5 本目は他論文からの参照曲線
  (`Ref. (Y0.56Al0.57B14)`)で、この論文のデータではないので正解データにありません。
  「凡例の数 = 系列の数」を前提にすると落ちます
- **27759/8 にはインセット**があり、主パネルと同じデータを拡大して再掲しています。
  軸校正・点座標は**主パネル**のものです
- **446/4(a) は最大目盛(400℃)より外側の 450℃ までデータがあります。**
  作図マージンの内側なので枠内ですが、目盛の外への外挿が要ります
- GT は描画されている点の**部分集合**のことがあります(例: 10939/5(c))。
  「全 GT 点がマーカー上に乗る」は確認済みですが、その逆は成り立ちません

## 含まれないもの

- **系列名(凡例との対応)。** `series_label` は全て `null` です。当リポジトリの正解データは
  曲線ごとの凡例ラベルを保持しておらず、推測で埋めるのは避けました。系列の順序は
  `ground_truth.json` の並び順そのままです
- **`sample_id` / `samplename`。** Starrydata の生CSVにはありますが、当リポジトリの
  収集パイプラインが保持していません
- **エラーバーの値**(17038/20816 には図中に描かれていますが数値は持っていません)

## 単位について

`unit_x`/`unit_y` は正解データに記録されている文字列をそのまま出しています。
今回の 21 枚は**印字軸と正解データが同じ単位空間にあることを確認済み**です
(全点が枠内に写像されることを機械的に確認し、さらにオーバーレイで目視確認しました)。
リポジトリ全体ではこれが成り立たない図もあります(registry が K で印字軸が ℃ など)が、
そういう図は今回除外しています。

## ライセンス・再配布

**21 枚すべてオープンアクセス論文の図で、`license_id` は `cc-by` です。CC BY は帰属表示を条件に
再配布を認めるので、公開リポジトリにコミットして構いません。** ただし 2 点、正確に扱ってください。

1. **バージョンを書かないでください。** この `cc-by` は OpenAlex の `license` フィールドの値で、
   バージョン番号を持ちません(CC BY 1.0/2.0/3.0/4.0 が全て同じ文字列になります)。
   表記は **「CC BY」** としてください。「CC BY 4.0」と書くには出版社のライセンス表示を
   論文ごとに確認する必要があります(当方は未確認です)
2. **改変の有無を明示してください。** `attribution.modified_from_original` が図ごとに入っています。
   **21 枚中 16 枚が `yes`** です(元のPDF埋め込み画像からの切り出し/向き補正)。
   CC BY では改変の明示が必要です。曲線の値そのものは変えていません。
   `no` は 5 枚(27759/25217、27759/25218、47534/49581、16111/15452、17038/20816)だけなので、
   **図ごとに `attribution.modified_from_original` を引いてください**(一律に扱うと誤りになります)

各図の `attribution.line` にそのまま使える帰属表示文が入っています。DOI は
`attribution.doi_url` です。

## 意図的に外した図

`fixtures.json` の `excluded` に理由つきで入れています。現時点で 1 枚:

**83/9049 — ピクセル単位のオラクルとしては使えません。** 導出ピクセルが描画マーカーから
離れます(最近傍インクまで中央値 6.4px。束に入れた図は 1.4px 以下)。
**この図は 2026-09-04 にお渡しした前回の束に含まれていました。**

> **訂正(2026-09-11)**: 2026-09-09 にお渡しした版では、ここに
> 「正解データの系統的な誤り」「正解 y が描画 y の約 0.85 倍」「原因調査は未着手」と
> 書いていましたが、**いずれも誤りでした**。
>
> - **0.85 という数字に根拠がありません。** 距離を最小化する補正フィットから出た値ですが、
>   この種の図ではフィットが縮退していて、**正常に重なっている図に同じ処理をしても
>   同じ係数が出ます**(改善量はゼロ)。測定のアーティファクトでした
> - **未調査でもありませんでした。** 2026-09-07 にオーナーが判断済みで、
>   `excluded_reason: harness_limit`(軸情報は印刷目盛と一致しており残差は軸の問題ではない。
>   古いスキャン図でマーカー中心の判定が原理的に曖昧。**GT の誤りを示す証拠はない**)。
>   当方が既存の判断を見落として報告しました
>
> 残る結論は「ピクセル単位のオラクルには使えない」ことだけです。

## 再生成

real-chart-bench 側で:

```
python scripts/export/build_starrydata3_e2e_fixtures.py <出力先>
```

図の追加・差し替えのご要望があれば、選定条件(オーナーレビュー済みの軸校正があること等)を
満たす候補が**他に 26 枚**あります。うち同一論文で複数図が揃うのは
**29352(6 枚)**、**28331(さらに 4 枚)**、**36342(3 枚)**、**4176 / 18869 / 10939(各 2 枚)**。
性質を指定していただければ選び直せます。
