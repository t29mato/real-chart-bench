## 3. LLM 10図評価の再現方法

```
python3 scripts/eval/prepare_llm_subset.py    # 10図を /tmp へ書き出す(決定的)
# 各モデルをサブエージェントとして起動し predictions.json を書かせる
python3 scripts/eval/archive_llm_subset.py    # 入力と生の回答をリポジトリへ
python3 scripts/eval/score_llm_predictions.py # 既存ハーネスで採点
python3 scripts/leaderboard/generate.py
```

生の回答は `data/llm_subset_n10/predictions/<model>.json` にあるので、
**モデルを再度呼ばなくても採点はやり直せる**。メトリクスを変えた場合も同じ回答に
適用できる。`_key.json` が fig_NN → figure_id の対応を持つ(モデルには渡していない)。

### この測定の弱点(結果を読むときに必ず併せて見ること)

1. **サンドボックスではない。** モデルはサブエージェントとして動くのでファイルツールを持つ。
   画像をリポジトリ外へ `fig_NN.png` と改名して複製し、正解をプロンプトに入れず、
   リポジトリを探索しないよう指示した。しかし Bash を持つエージェントが
   探しにいけばリポジトリに到達しうる。「不正が不可能」ではなく「緩和した」が正確な主張。
2. **4モデルで同一ディレクトリを共有させたのは設計ミス。** 禁じたのは `llm_eval/` の
   *外*を読むことだけなので、後発のモデルは先に完了したモデルの `predictions.json` を
   読める状態にあった。次回はモデルごとに独立したディレクトリを切り、
   共有領域は読み取り専用の入力だけにすること。
3. **n=10 はモデル間の順位を確定させるには小さすぎる。** 傾向を見るためのもの。
   `dataset_version` を `v0-eval-pilot-n112-llm-subset-n10` と別立てにしてあるので、
   112図の本評価と同じ表には並ばない。

## 4. 環境の注意(このリポジトリ共通)

- `python3` のみ。venv/pip は素で入っていない(セットアップ手順は過去メモ参照)。
- **import-linter は `lint-imports` で実行する。** `python3 -m importlinter.cli lint` は
  何も評価せず exit 0 を返す —— 偽のgreenになる。
- 報告前に必ず: `PYTHONPATH=$PWD/src python3 -m pytest -q` / `ruff check .` / `lint-imports`。
