# 合成図で学習したモデルの動作確認 — ChartQA(2026-10-05)

## 目的

合成図で学習したチャート専用モデル5つを real-chart-bench の97図で動かしたところ、点 F1 が 0.13〜0.29 と
非常に低かった(design §7.75 (1))。オーナー指摘「マシンや環境の差を知りたい。彼らのベンチマークで彼らの
モデルが期待通り出るか確認したほうが良い」。そこで、同じ環境・同じ読み込みと推論のコード
(`scripts/eval/chart2table/worker.py` の `Runner`)で、各モデルが学習・評価に使っている ChartQA の
テスト図を読ませた。

## 方法

- データ: ChartQA(vis-nlp/ChartQA、GitHub、GPL-3.0)のテスト図と正解の表から、乱数シード 20261005 で
  30図を抽出。`data/cache/` に置き、ローカルでの確認にのみ使う(再配布しない)。
- 指標: 正解の表と予測の表の数値セルを、相対 5% 以内で1対1に対応づけ、図ごとに
  再現率(対応した数 / 正解の数値の数)と適合率(対応した数 / 予測の数値の数)を出して平均する。
  行・列のラベルと順序は無視する。「正しい数値が出ているか」だけを見る確認で、論文の指標(RMS-F1 など)の
  再現ではない。壊れた環境(重みの誤り、前処理の誤り、プロンプトの誤り)ならここが崩れる。
- スクリプト: `scripts/eval/chart2table/sanity_chartqa.py <model> 30`(各モデルの venv で実行)。

## 結果

| モデル | 値の再現率 | 適合率 | 環境 |
|---|---|---|---|
| TinyChart-3B-768 | 0.920 | 0.869 | torch 2.0.1+cu118、transformers 4.37.2 |
| DePlot | 0.902 | 0.843 | torch 2.11.0+cu128、transformers 4.57.6 |
| Granite Vision 4.1 4B | 0.898 | 0.827 | 同上 |
| ChartGemma | 0.807 | 0.676 | 同上 |
| UniChart (base-960) | 0.791 | 0.781 | 同上 |

## 結論

5モデルとも、自分の領域の図(ChartQA)では数値の8〜9割を正しく出している。この環境・この読み込み方・
このプロンプトは機能している。real-chart-bench での低いスコアは環境の問題ではなく、合成図・ウェブの
統計グラフで学習したモデルが、実論文の実験グラフ(数値の x 軸、マーカー、対数軸、多系列)を読めていない
ことを示す。

途中で見つけた環境の問題(いずれも修正済み):
- DePlot はプロンプトを画像に描き込むためのフォントを Hub から取得する。オフライン実行ではキャッシュが要る。
- UniChart の重みは `.bin` のみで、safetensors だけを取得すると読み込めない。
- Granite Vision はリポジトリのコードが要る(`trust_remote_code`、公式リポジトリ)。
- TinyChart は UTF-8 モードが要る(`PYTHONUTF8=1`)。視覚塔は README のとおり TinyChart-3B-768-siglip を
  ローカルで参照する。
