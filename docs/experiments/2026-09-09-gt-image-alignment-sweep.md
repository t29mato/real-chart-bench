# GT↔画像の重なりを全件掃引した (2026-09-09)

**きっかけ**: Starrydata3 へ E2E フィクスチャを渡した際、`83/9049` を「GTと描画マーカーが
ずれている」として除外した。先方の指摘は的確だった —— **「`verified` が付いていてもGTが図と
一致しないことがあるなら、同じ原因で他の図も静かにずれているのでは」**。本メモはその掃引結果。

再現: `python scripts/eval/sweep_gt_image_alignment.py --json <出力>`

## 1. `verified` は何を保証していたのか

**「ペアリングの正しさ」であって「点が描画マーカーに乗ること」ではない。**

設計 §7.19 の検証手続きは、曲線数・値のレンジ・大小関係を印字軸と突き合わせるもの。
点ごとの位置は見ていない —— そもそも**それを見るためのピクセル軸データは 2026-08-30 まで
存在しなかった**(`axis_pixel_candidates.json`)。verified の大半はそれ以前(08-21〜08-22)に
付いている。したがって**「レンジは正しいが曲線の形が歪んでいる」は検証を素通りする**。

これは欠陥ではなく**当時できる検証の限界**だが、フラグの意味としては明記されていなかった。
なお「ペアリングは正しいがGTが疑わしい」を表す型は §7.48 で既に導入済みで、
`rejection_category: gt_suspect` + `GtSuspectStatus`(`llm_flagged` / `human_confirmed` /
`human_rejected`)が verified のまま共存できる。**自動チェックが上げられるのは `llm_flagged`
まで**で、`human_confirmed` へ昇格できるのは人間だけ(オーナー指示)。採点除外は
`excluded_reason` という別軸で、これも独立している。

## 2. 測り方

各図について、GT全点を軸読みで画素に写像(`PixelCalibration.to_pixel`)し、

| 指標 | 定義 |
|---|---|
| `d_true` | 各点から最近傍の「インク」(背景色から離れた画素)までの距離の中央値 |
| `d_null` | 同じものを、画像対角の2%だけ8方向にずらして測った中央値 —— **わざと外した配置の点数** |
| `ratio` | `d_true / d_null`。0に近い=重なりは本物、1前後=外した配置と大差ない |

`d_true` 単独では読めない。中空マーカーの図は正しく重なっていても `d_true ≈ マーカー半径` に
なるし、インクが密な図は何をしても小さくなる。`d_null` はそれを正規化するために要る。

**この指標の妥当性の裏取り**: 人手で `gt_wrong` が確定している `17044/20740` と
`18759/12217`、`gt_mismatch` の `10939/1530` を、既知情報を与えずに独立に上位へ拾えている。

## 3. 結果

**verified 139件のうち測定できたのは100件。** 測定できない39件の内訳: 軸読みが存在しない17件、
画像が無い16件、軸読みが不完全4件、軸読みが `excluded` 2件。

**84件が「重なっている」**(`ratio ≤ 0.5`)。フラグが立った16件は次の4群に分かれ、
**説明の付かない新規は1件だけ**だった。

### (a) 印字軸とGTの単位空間が違うだけ (5件) — GT誤りではない

`4173/20121`、`4965/13164`、`29352/29154`、`5902/15114`、`34286/33296`。
registry が K で印字軸が ℃、あるいはGTがSI単位のまま(例: `34286/33296` は
GT `W·m⁻¹·K⁻²` に対し印字軸 `μW·cm⁻¹·K⁻²` で 10⁴ 倍)。
**採点には影響しない** —— ハーネスは registry のレンジとGTだけを使い、印字ラベルを読まない。
影響するのは「印字軸を使う」用途だけで、これらは Starrydata3 への引き渡しからも既に除外済み
(`docs/interop/README.md`)。

### (b) 既に人手で確定済み (3件)

`17044/20740`(gt_wrong)、`18759/12217`(gt_wrong)、`10939/1530`(gt_mismatch)。
指標が独立に再発見した = 上記の裏取り。

### (c) 既にオーナー判断済み (1件) — `83/9049`

**2026-09-07 に `excluded_reason: harness_limit` として処理済みだった**
(「軸情報は印刷目盛と一致しており残差は軸の問題ではない。古いスキャン図でマーカー中心の
判定が原理的に曖昧。**GTの誤りを示す証拠はない**」)。掃引でも `ratio 0.44` と中間的で、
(a)や(b)のような明確な外れ方はしていない。

> **訂正**: 2026-09-09 に Starrydata3 へ「GT y が描画 y の約0.85倍」「原因調査は未着手」と
> 伝えたが、**どちらも誤り**。0.85 はオーバーレイの目視印象と、後述の縮退したフィットから
> 出た数字で、根拠がない。調査も未着手ではなく 09-07 に判断済みだった。先方には訂正済み。
> E2Eオラクルとして使えないという結論(除外)自体は変わらない。

### (d) 中空マーカー・密なインクによる見かけ上の高スコア (7件)

`18869/18874`、`18869/18875`、`47534/49581`、`3733/11780`、`44283/38973`、`44283/39566`、
`44283/39571`。いずれも `d_true` が 1〜3px 台で、中空マーカーの半径や線の太さで説明が付く。
オーバーレイでも問題なし。

### (e) 新規 (1件) — `44283/39578` FIGURE5(B)

**`d_true 3.16px` > `d_null 2.70px`。わざと外した配置より悪い唯一の未処理エントリ。**
低温側を3倍に拡大すると、**4本のGT曲線のうち3本がどの描画系列にも乗っていない**
(`x=0.00` の系列だけ合う)。

registry の evidence はレンジと大小関係を確認しており(「x-range 7.6-299.4K matches the
chart's 0-300K axis」)、**その確認は今も全部成り立っている**。§1のとおり、レンジ内に収まる
歪みは検証を通過する —— それがまさに実例として出た形。

`gt_suspect` / `llm_flagged` として記録した(`scripts/eval/record_alignment_sweep_2026_09_09.py`)。
**GT誤りとは呼んでいない**。この図の軸読み自体が `llm_candidate` のままなので、軸読み側の
誤りも排除できていない(ただし印字y目盛 0/3/6/9/12/15 は記録値と一致することを目視確認)。
**採点対象からは外していない** —— それはオーナー判断。

## 4. やってはいけないこと(実際にやって間違えた)

**補正フィット `y → a·y + b` の `a` を原因の手がかりにしてはいけない。**
`44283/39578` に当てると `a ≈ 0.85` で距離が 3.16→1.00 に改善するが、**対照として
正常な図に同じフィットを当てても `a ≈ 0.85` が出る**(`17044/20741`、`17040/21020`、
`44283/38968` —— いずれも identity で既に距離0なので改善は0)。インクが密な図では多数の
変換が距離0で並び、探索が任意の一つを返すだけ。**縮退であって証拠ではない。**
`83/9049` の「0.85倍」という誤報告はこれと目視印象が混ざって生まれた。

## 5. 残る穴

- **測定できない39件**(軸読み無し17・画像無し16・その他6)。軸読みが無い分は
  v1ブロッカーの「`llm_candidate` 82件の人手レビュー」と同じ根。
- **フラグが立った図のうち軸読みが `llm_candidate` の6件**は、軸とGTのどちらが原因か
  この指標では分離できない。`44283/39578` もこれに該当する。
- 指標は**マーカー中心ではなくインクまでの距離**を見ている。線が密な図では甘くなる。

## 6. 司令塔への確認事項

1. `44283/39578` を `human_confirmed` へ昇格させるか(人手確認が要る)。昇格させる場合、
   採点除外(`excluded_reason`)と上流(Starrydata)への報告も併せて判断が要る。
2. `verified` の意味を設計ドキュメントに明記するか。§1 の「ペアリングの検証であって
   点ごとの一致ではない」は、今回 Starrydata3 から指摘されるまで文章になっていなかった。
3. この掃引をCIに載せるか(現状は手動実行)。
