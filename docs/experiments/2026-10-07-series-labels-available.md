# 正解データに系列名を入れられる(2026-10-07)

オーナー指摘「starrydata の dataset のサンプル名を使えば正解データ作れると思いますよ」を確認した。
**指摘は正しい。系列名はソースにあり、こちらのパーサが捨てていた。**

## 何が起きていたか

`ThermoelectricMaterials_curves.csv.gz`(github.com/starrydata/starrydata_datasets、release latest)の
スキーマは次のとおりで、`composition` と `sample_id` を持つ。

```
SID, DOI, composition, sample_id, figure_id, figure_name,
prop_x, prop_y, unit_x, unit_y, x, y, created_at, updated_at, project_names, comments
```

`src/real_chart_bench/adapter/starrydata_csv.py:parse_curve_row` は両方を読まず、
系列名を `f"{prop_y} ({unit_y})"` で作っている。これが「1図内の全曲線が同一ラベル」
(論文 3.6 / 7.2)の原因である。**コーパスの性質ではなく、取り込みの欠落だった。**

## 実データでの確認

公開 CSV の先頭 1,615 行(gzip をストリームで部分展開)で確認した。

| | |
|---|---|
| `composition` が埋まっている行 | **1,615 / 1,615(100%)** |
| 3曲線以上の図 | 251 |
| そのうち composition が全曲線で異なる | **238(94.8%)** |
| 一部重複 | 3 |
| 全曲線で同一 | 10 |

`sample_id` も同様に曲線ごとに異なる。例(figure_id 79、10曲線、prop_y はすべて
"Seebeck coefficient"):

```
Pb1.00025Zn0.02Te1.02I0.0005
Pb1.0015Zn0.02Te1.02I0.003
Pb1.00075Zn0.02Te1.02I0.0015
Pb1.00015Zn0.02Te1.02I0.0003
...
```

## これで何ができるようになるか

1. **7.2 の限界(系列対応づけがラベルを使っていない)が解消できる。** 幾何だけの対応づけと
   ラベルを使う対応づけを比較できるようになる。
2. **ラベルを見る指標が計算できる。** CHART-Infographics の Task 6b は系列名の編集距離を
   コストに含む(3.5.3)。我々の側に名前がなかったので `name` 項を評価できていなかった。
3. **RMS が計算できる。** RMS の列見出しは系列名、行見出しは x の値である。前者が無かった。

## 重要な注意 — printed legend とは別物である

`composition` は**データベースの正規化された化学式**であり、**図に印字された凡例の文字列ではない**。
図の凡例が "x = 0.02" や "Sample A" の場合、`composition` は
"Pb1.00025Zn0.02Te1.02I0.0005" になる。

したがって:

- **文字列一致でラベルを採点するのは不公平である。** モデルは図を読んでいるので、
  印字された凡例しか出せない。実際 28498 で Opus 5.5 は `"label": "Lu0.1Bi1.9Te3"` と
  化学式を出したが、これは凡例に化学式が印字されていたからである。
- RMS の見出し類似項をそのまま適用すると、**凡例に化学式が印字されている図だけが有利になる**。
- 使える形は次のどれか:
  (a) 化学式を正規化して比較する(組成式のパーサが必要。凡例が化学式の図に限る)
  (b) ラベルを**同一性の検査にだけ使う**(系列を分けられたか、同じ試料に同じラベルを
      一貫して振れたか)。文字列の一致は見ない
  (c) 凡例の印字文字列を別途人手で記録し、`composition` との対応表を持つ

**(b) が最も公平で、追加の人手もいらない。** まずこれを実装すべきである。
