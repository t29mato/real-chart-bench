# 2026-08-16 パネル分割器の精度評価(全2,458枚 + 目視監査)

- Status: done
- 関連設計: [`docs/design/benchmark-architecture.md`](../design/benchmark-architecture.md) §7.12〜§7.14
- 再現スクリプト: [`scripts/eval/evaluate_panel_splitter.py`](../../scripts/eval/evaluate_panel_splitter.py)
- 対象: `data/raw/images/`(§7.13の本収集で得た全2,458枚の候補画像)

## 目的

司令塔承認(2026-08-16)により、§7.12で実装したパネル分割器(`detect_panel_grid` /
`PyMuPdfPanelSplitter`)を実際の収集済み画像全量に適用し、精度を評価する。単体テスト
(合成画像)だけでは実画像特有の失敗パターンを捉えられないため、deep-digitizerの
目視監査の方法論(design §7.10)を踏襲し、実際の画像をClaude自身が目視で確認した。

## 実行1回目: クラッシュ発覚

全2,458枚に適用した初回実行で**957枚(39%)がクラッシュ**(`IndexError: string index
out of range`)。原因は`_LABELS`(a-z、26文字)を超えるパネル数を検出した場合に
ラベル配列の範囲外アクセスが発生すること。実画像(JPEG圧縮ノイズ・アンチエイリアス等)
はgutter検出が過敏に反応し、26個を超える「パネル」を検出するケースが実在した
(合成テスト画像だけでは想定していなかった実データ特有の問題)。

**修正**: `max_panels`パラメータを追加(デフォルト26=ラベル文字数上限)。検出数が
上限を超えた場合はクラッシュせず「グリッド未検出」として元画像1枚を返すフォールバックに
変更(既存の「自信が持てない場合はクロップしない」という設計方針の自然な拡張)。

## 実行2回目: 目視監査で発覚した誤検出パターン

修正後(クラッシュ0件)の統計:

| max_panels | multi_panel検出率 | 備考 |
|---|---|---|
| 12(現実的な上限で実行) | 26.2%(645/2,458) | |

12という上限で多くの画像が「too many, fallback」となっていたため、実際に検出された
645件について目視監査(8枚を詳細確認)したところ、**系統的な誤検出パターン**を発見:

- **軸目盛りストリップ・回転した軸ラベルテキストが別パネルとして切り出される**:
  単一チャート画像(SID 14609)が4パネルとして誤検出。実際の`panel_a`/`panel_b`を
  確認すると、軸の罫線の断片のような**数ピクセル幅の細い帯**だった
- **複合図の軸ラベルテキストがパネルとして分離**(SID 17036、真の2パネルが8パネルに)
- **パネルラベル文字"(a)"の括弧がスライスされる**(SID 21396、真の2パネルが6パネルに)

## 修正: 最小パネルサイズフィルタ

これらはいずれも「画像サイズに対して極端に細い帯」という共通パターンだったため、
`min_panel_size_fraction`(デフォルト5%)を追加。行/列の帯が画像の対応する辺の
5%未満しかない場合はそのまま実パネル境界として扱わず除外する(§7.12の設計哲学
「自信が持てないgutterはgutterとして扱わない」の直接的な拡張)。TDDでこの実データ起因の
バグを再現する境界テストを追加(`test_thin_sliver_band_does_not_produce_spurious_extra_panels`)。

## 結論・推奨事項

1. **`embedded`(PDF埋め込みラスター画像)に対しては実用的な精度**: 目視確認した2件の
   真の2×2グリッドはいずれも正確に4分割された。軸ラベル・目盛りの誤検出は
   `min_panel_size_fraction`フィルタで解消。
2. **`page_render`(ページ全体レンダリング)への適用は非推奨**: 図表以外の本文・見出し・
   段組みを含むため、単純な背景gutterヒューリスティックでは図領域とテキスト領域を
   区別できない。**実運用のペアリングusecaseでは、パネル分割器は`source=embedded`の
   画像にのみ適用し、`page_render`画像には適用しない設計にすべき**(司令塔確認事項として
   次アクションに計上。現時点ではdomain/adapter層の実装自体は変更せず、呼び出し側の
   利用方針として記録)。
3. **複合図×ネストされたインセットの組み合わせでunder-segmentationが残る**
   (SID 46278の例)。既知の限界として記録し、次の技術調査候補とする(現時点では
   自動化投資を追加しない、という既定方針を維持)。
4. **`min_panel_size_fraction`フィルタの副作用**: 導入後にmulti-panel検出率が
   26.2%→53.5%に「上昇」した。これは細断片ノイズが除去されたことで、以前は
   `max_panels`上限超過によりフォールバックしていた画像の多くが、正しい少数パネル数
   (2〜6枚程度)として認識され直したため(悪化ではなく改善の副産物)。
